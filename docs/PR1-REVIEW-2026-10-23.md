## Reprodução do timeout

`tests/fixtures/upstash-timeout.ts` usa `@upstash/ratelimit@2.0.8` e `@upstash/redis@1.37.0`, sem mock desses módulos. Um servidor HTTP em `127.0.0.1`, com porta aleatória, retém a resposta Redis até a conclusão da verificação. O timeout do SDK é reduzido a 30 ms somente nesse teste; a configuração da aplicação não foi alterada. A execução fica em subprocesso para não herdar os mocks dos demais testes.

Antes da correção, o SDK retornou timeout e o wrapper devolveu `{ success: true, remaining: 0 }`. A nova suíte produziu oito falhas esperadas: SDK/wrapper, quatro rotas, Supabase 429 e dois desfechos do layout. Após a correção:

```json
{"sdk":{"success":true,"reason":"timeout"},"application":{"success":false,"remaining":0,"unavailable":true}}
```

Isso reproduz a falha da aplicação com o SDK e transporte HTTP reais contra serviço local controlado. Não constitui ensaio de indisponibilidade em uma instância Upstash externa. A documentação oficial descreve o comportamento: [Upstash — Timeout](https://upstash.com/docs/redis/sdks/ratelimit-ts/features#timeout).

O build usa modo de produção; o E2E usa servidor de desenvolvimento. Os testes de indisponibilidade das rotas executam a política de produção por unidade. O bloqueio de envios concorrentes é local ao formulário: não equivale a idempotência entre abas, clientes ou retentativas após falhas de rede.

## CI e preview da Vercel

O CI do commit inicial foi confirmado como aprovado: [Verify portal, execução 39025865874](https://github.com/fbmoulin/site-2avara-next/actions/runs/39025865874).

O preview inicial [dpl_HGFk5B2XJkoEMcbTTK6xKXGeZ39k](https://vercel.com/felipes-projects-de1c8fbd/site-2avara-next/HGFk5B2XJkoEMcbTTK6xKXGeZ39k) falhou ao coletar dados de `/artigos/[slug]`. Compilação e TypeScript terminaram; `generateStaticParams()` tentou consultar artigos e recebeu `ECONNREFUSED 127.0.0.1:5432`. Esse resultado é diferente do build local, que recebe uma conexão descartável válida.

A API de listagem das variáveis desse projeto retornou HTTP 403. Não há Vercel CLI autenticada disponível no ambiente para o fallback. Assim, não foi possível confirmar se `DATABASE_URL` está ausente, fora do escopo Preview ou configurada para localhost. O endereço observado nos logs não serve como banco do preview hospedado.

O estado do CI/preview do novo SHA é registrado na atualização do PR. Uma falha de configuração do preview não é tratada como autorização para usar banco ou segredos de produção nem para ocultar a consulta do build.
